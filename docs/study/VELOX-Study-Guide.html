١. المشروع في دقيقة

VELOX منصة توصيل لمدينة سمنود: العميل يطلب أكل من مطعم، أو "مشوار" (يشتري له حاجة من أي مكان). المطعم يجهّز، والمندوب يوصّل، والأدمن يتابع كل حاجة.
المستخدمبيعمل إيهالشاشة بتاعته
العميل (CUSTOMER)يتصفح المطاعم، يطلب، يدفع كاش أو أونلاين، يتابع المندوب على الخريطة، يقيّمالتطبيق + الموقع
المطعم (RESTAURANT)يستقبل الطلب بصوت، يقبل أو يرفض، يقول "جاهز"، يعدّل المنيو والأسعارصفحة المطعم في التطبيق
المندوب (DRIVER)يبقى أونلاين، ياخد الطلب، يستلمه، يسلّمه، يشوف أرباحهصفحة المندوب في التطبيق
الأدمن (ADMIN)يدير المستخدمين والمطاعم والمناطق والكوبونات والشكاوى ويشوف الإحصائياتلوحة التحكم

رحلة طلب واحد (اتجربت فعلاً: الطلب ORD-1009)

العميل يطلب←المطعم يسمع صوت ويقبل←المطعم: جاهز←المندوب: خد الطلب←استلمت←سلّمت←العميل يقيّم

٢. الصورة الكبيرة: Client و Server

أي نظام زي ده عبارة عن حاجتين:
• Client (العميل/الواجهة): اللي المستخدم بيلمسه: تطبيق الموبايل والموقع. مبيخزنش داتا مهمة، هو بيسأل السيرفر بس.
• Server (السيرفر/الباك إند): برنامج Java شغال على جهاز، بيستقبل الطلبات، يتأكد من الصلاحيات، يكلم قاعدة البيانات، ويرجّع الرد.
تطبيق Flutter / الموقع⇄ HTTP + JSON ⇄سيرفر Spring Boot (Java)⇄ JDBC ⇄PostgreSQL

يعني إيه HTTP وREST وJSON؟

  • HTTP: اللغة اللي الواجهة والسيرفر بيتكلموا بيها. كل طلب ليه Method وعنوان: GET /api/zones = "هاتلي المناطق".
  • REST: طريقة تنظيم العناوين: GET قراءة، POST إنشاء، PUT/PATCH تعديل، DELETE مسح.
  • JSON: شكل الداتا اللي بتتبعت: {"code":"SAMANNOUD","fee":15}.
  • Status codes: 200 تمام، 201 اتعمل، 204 تمام من غير رد، 400 بيانات غلط، 401 مش مسجّل دخول، 403 مش مسموحلك، 404 مش موجود، 429 محاولات كتير، 500 خطأ في السيرفر.

السيرفر نفسه متقسّم ٣ طبقات (Layered Architecture)

Controller
يستقبل الطلب←Service
القواعد والصلاحيات←Repository
SQL عن طريق JDBC←Database
ليه نقسّم؟ عشان كل طبقة ليها شغلانة واحدة. لو غيّرنا قاعدة البيانات نغيّر الـ Repository بس. ولو عايزين نختبر القواعد نختبر الـ Service من غير HTTP.

٥. Maven (Apache Maven) — نفس اللي الدكتور بعته

Maven بيعمل ٣ حاجات: (١) ينزّل المكتبات لوحده بدل ما نضيف JAR بإيدنا (زي ما الدكتور عمل مع JDBC driver في NetBeans: Add JAR/Folder)، (٢) يبني المشروع لملف JAR واحد، (٣) يشغّل الاختبارات.

ملف pom.xml (الجزء المهم منه)

<!-- بدل ما ننزّل JDBC driver بإيدنا ونضيفه في Libraries، بنكتب السطرين دول -->
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>          <!-- JDBC driver -->
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-jdbc</artifactId>   <!-- JdbcTemplate + connection pool -->
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>   <!-- JUnit 5 + Assertions -->
    <scope>test</scope>
</dependency>

المكتبات اللي في المشروع: spring-boot-starter-web (السيرفر)، -validation (التحقق من البيانات)، -jdbc، postgresql، flyway-core، springdoc-openapi (Swagger)، و للاختبارات: spring-boot-starter-test وtestcontainers وjunit-jupiter، وأدوات فحص: jacoco (نسبة تغطية الاختبارات) وspotbugs + findsecbugs (يدوّر على ثغرات في الكود).

مفاهيم لازم تعرفها

  • Primary Key: رقم مميز لكل صف (id). وForeign Key: عمود بيشاور على صف في جدول تاني (orders.store_id → stores.id).
  • Normalization: أصناف الطلب في جدول لوحدها (order_items) بدل ما نكررها في orders.
  • Transaction: كذا عملية تنجح مع بعض أو تتلغي مع بعض. مثلاً إنشاء الطلب + أصنافه + خصم المحفظة.
  • Index: بيسرّع البحث (زي فهرس الكتاب).
  • Migration: كل تعديل على الجداول في ملف جديد برقم أكبر. Flyway بيشغّل اللي لسه ماتشغلش بس، وبيسجّل ده في جدول flyway_schema_history.
  • الأسعار متخزنة NUMERIC وفي Java BigDecimal (مش double) عشان الفلوس متتلخبطش في الكسور.

٧. JDBC — طريقة الدكتور وطريقتنا

JDBC (Java Database Connectivity) هي الطريقة اللي Java بتكلم بيها أي قاعدة بيانات. كل قاعدة بيانات ليها Driver (SQL Server ليه sqljdbc اللي الدكتور بعته، وPostgreSQL ليه postgresql).

١) جملة الاتصال (Connection String)

اللي الدكتور شرحه (SQL Server)اللي عندنا (PostgreSQL)
البروتوكولjdbc:sqlserver://jdbc:postgresql://
السيرفرlocalhost\SQLEXPRESSaws-0-eu-north-1.pooler.supabase.com:5432 (أو localhost:5432 على جهازك)
قاعدة البياناتdatabaseName=DEPI_Library/postgres (أو /velox محلياً)
التشفيرencrypt=true; trustServerCertificate=truesslmode=require
اليوزر والباسوردجوه الكودبرّه الكود في متغيرات بيئة DB_USER وDB_PASSWORD (عشان الباسورد ميترفعش على GitHub)

في application.properties:

spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5432/velox}
spring.datasource.username=${DB_USER:velox}
# ${DB_URL:...} = خد القيمة من متغير البيئة DB_URL، ولو مش موجود استخدم اللي بعد النقطتين

٢) نفس الاستعلام بالطريقتين

الطريقة الخام (زي الكورس):

String url = "jdbc:postgresql://localhost:5432/velox";
try (Connection con = DriverManager.getConnection(url, user, password);
     PreparedStatement ps = con.prepareStatement(
         "SELECT * FROM delivery_zones WHERE code = ? AND active")) {
    ps.setString(1, code);                       // ? بتتملي بأمان — ده بيمنع SQL Injection
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            String name = rs.getString("name_ar");
            BigDecimal fee = rs.getBigDecimal("fee");
        }
    }
}   // try-with-resources بيقفل الاتصال لوحده

طريقتنا بـ JdbcTemplate (من ZoneRepository.java الحقيقي):

@Repository
public class ZoneRepository {

    // RowMapper: بيحوّل كل صف من ResultSet لأوبجكت Java
    private static final RowMapper<DeliveryZone> ZONE = (rs, n) -> new DeliveryZone(
            rs.getString("code"), rs.getString("name_ar"), rs.getString("name_en"),
            rs.getString("kind"), rs.getBigDecimal("fee"), rs.getInt("eta_min"),
            rs.getBoolean("active"), rs.getInt("sort_order"));

    private final JdbcTemplate db;

    public ZoneRepository(JdbcTemplate db) { this.db = db; }   // Dependency Injection

    public Optional<DeliveryZone> findActive(String code) {
        return db.query("SELECT * FROM delivery_zones WHERE code = ? AND active", ZONE, code)
                 .stream().findFirst();
    }

    public void insert(DeliveryZone z) {
        db.update("INSERT INTO delivery_zones (code, name_ar, name_en, kind, fee, eta_min, active, sort_order) "
                + "VALUES (?,?,?,?,?,?,?,?)", z.code(), z.nameAr(), z.nameEn(), z.kind(), z.fee(),
                z.etaMinutes(), z.active(), z.sortOrder());
    }
}
الفرق: JdbcTemplate بيعمل نفس خطوات JDBC بالظبط (Connection ← PreparedStatement ← ResultSet ← close) بس هو اللي بيفتح ويقفل، ومعاه Connection Pool (HikariCP) يعني بيحتفظ باتصالات مفتوحة جاهزة بدل ما يفتح اتصال جديد مع كل طلب، فالسيرفر بيبقى أسرع.
أهم حاجة أمنياً: إحنا مبنلزقش كلام المستخدم جوه الـ SQL أبداً. دايماً ?. لو كتبنا "... WHERE code = '" + code + "'" حد ممكن يكتب ' OR 1=1 -- ويقرا كل الجدول. ده اسمه SQL Injection، وجرّبناه في اختبار الاختراق ومنفعش.

طلب واحد من أوله لآخره: GET /api/zones

  1. التطبيق يبعت GET https://.../api/zones.
  2. Filters الأول: SecurityHeadersFilter بيحط رؤوس الأمان، و CORS بيتأكد إن الطلب جاي من موقع مسموح.
  3. Controller (ZoneController) يستقبله: 
    @RestController
public class ZoneController {
    private final ZoneService zones;
    public ZoneController(ZoneService zones) { this.zones = zones; }

    @GetMapping("/api/zones")
    public List<ZoneView> zones() {
        return zones.active().stream().map(ZoneView::of).toList();
    }

    @PostMapping("/api/admin/zones")
    @ResponseStatus(HttpStatus.CREATED)
    public void create(@CurrentUser AuthUser me, @Valid @RequestBody ZoneRequest req) {
        zones.create(me, req.toZone());     // الـ Service بيتأكد إن me أدمن
    }
}
  4. Service (ZoneService) فيه القواعد: مين مسموحله، والبيانات صح ولا لأ.
  5. Repository (ZoneRepository) يعمل الـ SQL (شفناه فوق).
  6. Spring يحوّل الـ List<ZoneView> لـ JSON أوتوماتيك (مكتبة Jackson) ويرجّعه بـ 200.

أهم الـ Annotations

Annotationمعناها
@RestControllerالكلاس ده بيستقبل طلبات HTTP ويرجّع JSON
@GetMapping / @PostMapping / @PutMapping / @PatchMapping / @DeleteMappingالعنوان والـ Method
@PathVariableجزء من العنوان: /api/orders/{code}
@RequestBody + @Validالـ JSON اللي جاي يتحوّل لأوبجكت ويتراجع (مثلاً @NotBlank, @Email, @Size)
@Service / @Repository / @ComponentSpring يعمل منه نسخة واحدة ويديها لأي حد محتاجها (Bean)
@Transactionalكل اللي جوه الميثود ينجح مع بعض أو يتلغي مع بعض

@CurrentUserAnnotation إحنا عاملينها: بتجيب المستخدم من التوكن (CurrentUserResolver)

أي مشكلة بنرمي ApiException بكود ورسالة، وGlobalExceptionHandler (@RestControllerAdvice) بيحوّلها لرد JSON ثابت الشكل. ومبنرجعش أبداً تفاصيل الخطأ الداخلية (server.error.include-stacktrace=never) عشان المهاجم ميعرفش حاجة عن الكود.

Swagger

لو شغّلت السيرفر محلياً افتح http://localhost:8080/swagger-ui.html: هتلاقي كل العناوين وتقدر تجرّبها. في السيرفر الحقيقي مقفولة (VELOX_API_DOCS=false) عشان الأمان.

١) الباسوردات

static final int ROUNDS = 210_000;

    ...

}
  • الباسورد مش متخزن أبداً، بنخزن الـ hash بس. و Hash ده اتجاه واحد: مينفعش يرجع باسورد.

٢) تسجيل الدخول (Token)

// TokenService.java — توكن موقّع بـ HMAC-SHA256
// شكله:  base64(publicId) . version . expiry . signature
  • بعد الدخول السيرفر يدّي التطبيق توكن، والتطبيق يبعته مع كل طلب: Authorization: Bearer <token>.

٣) الصلاحيات (Authorization)

  • كل مستخدم ليه Role. الـ Service بيتأكد قبل أي عملية: المطعم يشوف طلباته هو بس، والمندوب ميقدرش يقبل طلب مكان المطعم.
  • كل الأرقام اللي في العناوين publicId عشوائي أو كود (ORD-1009)، و دايماً بنتأكد إن الطلب ده بتاعك. ده بيمنع IDOR (إنك تغيّر رقم في اللينك وتشوف داتا حد تاني).

import static org.junit.jupiter.api.Assertions.*;
import org.junit.jupiter.api.Test;

class PasswordHasherTest {

    private final PasswordHasher hasher = new PasswordHasher();

    @Test
    void hashMatchesOnlyTheRightPassword() {
        String hash = hasher.hash("correct horse");
        assertTrue(hasher.matches("correct horse", hash));     // الباسورد الصح يدخل
        assertFalse(hasher.matches("correct horsE", hash));    // حرف واحد غلط = مرفوض
        assertFalse(hasher.matches(null, hash));
    }

    @Test
    void samePasswordGivesDifferentHashesAndNoClearText() {
        String a = hasher.hash("velox12345");
        String b = hasher.hash("velox12345");
        assertNotEquals(a, b, "random salt");                   // الـ salt شغال
        assertFalse(a.contains("velox12345"));                  // الباسورد مش ظاهر
    }
}

  • StatelessWidget: شاشة أو جزء مبيتغيرش. StatefulWidget: بيتغير، وsetState() بيعيد رسمه.

خطوات النشر:

  1. ندخل السيرفر بـ SSH، نحدّثه، ونقفل الدخول بالباسورد.
  2. Firewall: نفتح بورتات 22 (SSH) و80 و443 (الويب) بس.
  3. نسطّب Docker.
  4. نبني الـ image من backend/Dockerfile (شرحه تحت) ونشغّله بـ docker compose، مع restart: always عشان يقوم لوحده لو السيرفر عمل restart.
  5. Caddy قدامه كـ Reverse proxy: بياخد شهادة HTTPS مجانية من Let's Encrypt لوحده ويوصّل الطلبات للـ API على 8080.
  6. لينك ثابت (دومين أو IP)، ونبني التطبيق بـ --dart-define=API_URL=https://... فاللينك يبقى جوه التطبيق وميتغيرش.

الـ Dockerfile (مرحلتين — Multi-stage build)

# المرحلة 1: نبني بـ JDK كامل
FROM eclipse-temurin:17-jdk-alpine AS build
WORKDIR /src
COPY backend/mvnw backend/pom.xml ./backend/
RUN cd backend && ./mvnw -q -B dependency:go-offline     # ينزّل المكتبات (cache)
COPY backend/src ./backend/src
RUN cd backend && ./mvnw -q -B -DskipTests package && cp target/velox-backend-*.jar /src/app.jar

# المرحلة 2: نشغّل على JRE صغير بيوزر عادي (مش root)
FROM eclipse-temurin:17-jre-alpine
RUN addgroup -S velox && adduser -S velox -G velox
COPY --from=build /src/app.jar app.jar
USER velox
ENV PORT=8080 VELOX_API_DOCS=false
HEALTHCHECK CMD wget -qO- http://localhost:8080/api/zones || exit 1
ENTRYPOINT ["sh", "-c", "exec java $JAVA_OPTS -jar app.jar"]
ليه مرحلتين؟ الـ image النهائي فيه الـ JAR والـ JRE بس، من غير JDK وMaven والكود. فبيبقى أصغر وأأمن. وHEALTHCHECK بيخلّي Docker يعرف لو السيرفر وقع.

docker-compose.yml

للتطوير على جهازك: docker compose up -d db بيشغّل PostgreSQL بس. ولو عايز السيستم كله: docker compose --profile app up -d --build بيشغّل قاعدة البيانات والـ API مع بعض.

١٥. تطبيق الأندرويد والتحديثات

  • البناء: flutter build apk --release --split-per-abi: نسخة لكل نوع معالج (arm64 للموبايلات الحديثة) + نسخة universal.

  • Google Play: مأجّل. ملف .aab جاهز لو قررنا نرفع.

١٨. أسئلة الدكتور المتوقعة بالإجابات

س: اشرح المشروع في دقيقة.
منصة توصيل لسمنود فيها ٤ أنواع مستخدمين: عميل ومطعم ومندوب وأدمن. السيرفر Java Spring Boot وقاعدة البيانات PostgreSQL والتطبيق Flutter. الطلب بيمشي من العميل للمطعم للمندوب لحد ما يتسلّم، وكل ده بيتحدث مباشر.
س: إزاي السيرفر بيكلم قاعدة البيانات؟
بـ JDBC عن طريق JdbcTemplate من Spring. جملة الاتصال jdbc:postgresql://host:5432/db في application.properties، واليوزر والباسورد من متغيرات البيئة. وكل استعلام PreparedStatement بـ ?.
س: إيه الفرق بين اللي عملتوه وبين DriverManager.getConnection اللي شرحناه؟
نفس الفكرة. JdbcTemplate جوّاه بيعمل Connection وPreparedStatement وResultSet وclose، بس بيستخدم Connection Pool بدل ما يفتح اتصال جديد كل مرة، وبيقلل الكود المكرر.
س: إيه هو SQL Injection وإزاي منعتوه؟
إن المستخدم يكتب SQL جوه خانة إدخال فيتنفذ. منعناه بإن كل القيم بتتبعت كـ parameters (?) مش بنلزقها في النص. وجرّبنا الهجوم في الـ Pentest ومنجحش.
س: الباسورد متخزن إزاي؟
PBKDF2-HMAC-SHA256 بـ 210,000 لفة وsalt عشوائي لكل باسورد. مش بنخزن الباسورد نفسه أبداً، وعليها اختبار JUnit (PasswordHasherTest).
س: الدخول بيشتغل إزاي؟
بعد ما الباسورد يتأكد، السيرفر يدّي توكن موقّع بـ HMAC-SHA256 فيه رقم المستخدم والـ version وتاريخ الانتهاء. التطبيق يبعته مع كل طلب، والسيرفر يتأكد من التوقيع. ولو الباسورد اتغير الـ version بيزيد فالتوكنات القديمة تبطل.
س: عندكم كام اختبار وأنواعهم إيه؟
97 اختبار JUnit (unit + integration بـ Testcontainers)، و45 فحص على السيرفر الحقيقي، وSelenium للموقع، وPostman للـ API، وJMeter للأداء (100 مستخدم، p95 = 116ms)، و6 اختبارات Flutter.
س: إيه الفرق بين Unit test وIntegration test؟
Unit بيختبر كلاس واحد لوحده من غير قاعدة بيانات ولا سيرفر (زي OrderStatusTest). Integration بيشغّل التطبيق كله مع PostgreSQL حقيقي وبيبعت طلبات HTTP (زي OrderApiTest).
س: اكتب اختبار JUnit دلوقتي.
@Test void accepted() { assertTrue(OrderStatus.PLACED.canMoveTo(OrderStatus.ACCEPTED, Actor.RESTAURANT)); }: Arrange/Act/Assert.
س: إيه لازمة Maven؟
بينزّل المكتبات لوحده من pom.xml (بدل Add JAR/Folder)، وبيبني المشروع لـ JAR، وبيشغّل الاختبارات بـ mvn test.
س: لو المطعم مردّش على الطلب؟
StaleOrderCloser بيشتغل كل شوية (@Scheduled)، ولو عدّى 15 دقيقة بيلغي الطلب ويرجّع الفلوس ويبلّغ العميل.
س: المطعم بيعرف بالطلب الجديد إزاي؟
SSE: التطبيق فاتح اتصال مع /api/events، فالسيرفر يبعت الطلب فوراً والتطبيق يعمل صوت واهتزاز. ولو التطبيق مقفول يوصل Push من Firebase.
س: إيه يمنع العميل يغيّر سعر الطلب؟
التطبيق بيبعت المنتجات والكميات بس، والسيرفر بيحسب السعر من قاعدة البيانات (PricingService).
س: إيه يمنع المندوب يشوف طلبات مطعم مش بتاعه أو عميل يشوف طلب حد تاني؟
كل Service بيتأكد من الـ Role ومن إن الطلب ده يخص المستخدم ده (منع IDOR). ولو مش بتاعك الرد 403 أو 404.
س: الجداول اتعملت إزاي؟
بـ Flyway: ملفات V1 لـ V7. أول ما السيرفر يشتغل بيشغّل اللي لسه ماتشغلش بالترتيب، فأي جهاز جديد بيطلع بنفس الجداول.
س: ليه Docker؟ والـ Dockerfile فيه مرحلتين ليه؟
عشان السيرفر يشتغل بنفس الشكل على أي جهاز. المرحلة الأولى بتبني بـ JDK وMaven، والتانية بتشغّل الـ JAR بس على JRE صغير بيوزر مش root، فالـ image أصغر وأأمن.
س: السيرفر مستضاف فين؟
دلوقتي على جهاز نبيه مع Cloudflare Tunnel وقاعدة البيانات على Supabase. وبننقله لسيرفر Hetzner (2 vCPU / 4GB / Ubuntu) بـ Docker وCaddy للـ HTTPS ولينك ثابت.
س: إيه أخطر ثغرة لقيتوها؟
التطبيق كان بيقبل أي لينك سيرفر من قناة عامة، فمهاجم ممكن يحوّل التطبيق لسيرفر بتاعه ويسرق الباسوردات. قفلناها بإن التطبيق يقبل لينكات Cloudflare بس، والنسخة النهائية لينكها ثابت جوه الكود.
س: ليه Flutter؟
كود واحد طلع منه أندرويد وويب. والتطبيق بلغتين عربي وإنجليزي، والاتجاه بيتظبط لوحده.
س: إيه الـ Layers في السيرفر؟
Controller (يستقبل HTTP) ← Service (القواعد والصلاحيات) ← Repository (SQL) ← Database.
س: ليه BigDecimal مش double في الفلوس؟
double بيعمل أخطاء كسور (0.1 + 0.2 ≠ 0.3). BigDecimal دقيق، والعمود في قاعدة البيانات NUMERIC.
س: لو 100 واحد طلبوا في نفس الوقت؟
جرّبناها بـ JMeter: 4000 طلب، صفر أخطاء، و95% أسرع من 116ms. والـ Connection Pool والـ ConcurrentHashMap بيخلّوا السيرفر يستحمل الطلبات اللي جاية مع بعض.

١٩. معمل: شغّل المشروع بإيدك (قدام الدكتور)

أ) السيرفر في NetBeans أو من الترمينال

  1. سطّب JDK 17 وDocker Desktop.
  2. هات الكود: git clone (اطلب اللينك من نبيه).
  3. شغّل قاعدة بيانات محلية: docker compose up -d db (PostgreSQL على 5432، يوزر وباسورد velox).
  4. في NetBeans: File ← Open Project واختار فولدر backend (هيعرف إنه Maven project لوحده).
  5. اعمل متغير بيئة VELOX_TOKEN_SECRET بأي كلام طوله 32 حرف أو أكتر (في NetBeans: Project Properties ← Run ← Environment). أو من الترمينال: 
    cd backend
set VELOX_TOKEN_SECRET=local-dev-secret-change-me-at-least-32-chars
mvnw spring-boot:run
  6. افتح http://localhost:8080/swagger-ui.html وجرّب GET /api/zones.
  7. الاختبارات: كليك يمين على المشروع ← Test، أو mvnw test (لازم Docker يكون شغال عشان Testcontainers).

ب) شوف الداتا بإيدك (SQL)

docker exec -it velox-db psql -U velox -d velox
SELECT code, name_ar, fee FROM delivery_zones;
SELECT code, status, total FROM orders ORDER BY id DESC LIMIT 5;
\dt              -- كل الجداول

ج) التطبيق

  1. سطّب Flutter، وبعدين cd mobile وflutter pub get.
  2. flutter run -d chrome للويب، أو وصّل موبايل وشغّل flutter run.
  3. من الإعدادات حط لينك السيرفر http://localhost:8080 (في الويب) أو IP جهازك (في الموبايل).

د) ديمو قدام الدكتور (5 دقايق)

  1. افتح ٣ شاشات: عميل، ومطعم، ومندوب.
  2. العميل يطلب ← المطعم يسمع صوت ويقبل ثم "جاهز" ← المندوب "خد الطلب" ثم "استلمت" ثم "سلّمت" ← العميل يشوف التتبع ويقيّم.
  3. افتح Swagger ووريه العناوين، وشغّل mvnw test ووريه الاختبارات بتعدّي.
  4. جرّب قدامه SQL Injection في خانة الدخول (' OR 1=1 --) ووريه إنها اترفضت.
