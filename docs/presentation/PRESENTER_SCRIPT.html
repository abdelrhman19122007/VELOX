٢) السلايدات واحدة واحدة

1 — VELOX (الغلاف)هدى40 ثانية

"صباح الخير. إحنا فريق VELOX، مشروع تخرج مبادرة رواد مصر الرقمية، تراك Penetration Testing. VELOX منصة توصيل أكل لمدينة سمنود: Your favorite food, at your doorstep. وبما إننا تراك أمن، فهتلاقوا الأمان جوه كل حاجة هنعرضها."

2 — The problemهدى1 دقيقة

"في سمنود الطلب لسه بالتليفون. العميل مش عارف الأسعار ولا رسوم التوصيل، ومش عارف الطلب فين. والمطعم الطلبات بتجيله من كذا مكان، وبتحصل غلطات في الأصناف والعناوين، ومعندوش مناديب. الفرصة: منصة واحدة تخلي الطلب واضح وسريع ومنظّم."

3 — Our solutionهدى1 دقيقة

"VELOX بيربط العميل والمطعم والمندوب في سيستم واحد، وفيه لوحة تحكم للإدارة. عندنا منيو حقيقي بالصور والأسعار، وطلب واضح بالسعر الكامل قبل التأكيد، وتتبع لايف، والدفع كاش أو من المحفظة، وشاشة لكل دور، ولوحة أدمن. رؤيتنا: نخلي التوصيل في سمنود أذكى وأسهل." وبعدين: "فادي هيوريكم الأدوار."

4 — Four connected rolesفادي1 دقيقة

"عندنا 4 أدوار: العميل بيطلب ويدفع ويتابع. المطعم بيستقبل ويقبل ويجهّز. المندوب بياخد الطلب ويوصّله. والأدمن بيدير كل حاجة. أول 3 أدوار في نفس التطبيق، والسيرفر هو اللي بيحدد كل حساب يشوف إيه ويعمل إيه. ده اسمه Role-based access control."

5 — Customer experienceفادي1.5 دقيقة

"رحلة العميل 5 خطوات: يستكشف المطاعم الحقيقية، ويطلب وهو شايف السعر الكامل، ويدفع كاش أو من المحفظة أو بكوبون، ويتابع المندوب على الخريطة، ويوصله إشعار في كل خطوة." عن الدفع قول بالظبط: "الكاش شغال، والمحفظة فيها المرتجعات، وفوري وفودافون كاش متركّبين في وضع تجريبي (Sandbox) ومستنيين حساب تاجر." وبعدين: "رحيق هتوريكم المطعم."

6 — Restaurant managementرحيق1 دقيقة

"المطعم بيشتغل من الموبايل: الطلب الجديد بيرن من غير Refresh، يقبل أو يرفض بسبب، ويقول جاهز، ويشوف كل طلب مستني بقاله قد إيه، ويغيّر الأسعار ويقفل الصنف اللي خلص. وكسبان عملاء جداد، وطلبات مكتوبة واضحة، ومناديب من غير ما يعيّن حد. على VELOX دلوقتي: مطعم ناصف بـ 111 صنف بالصور، و3 كافيهات منيوهاتهم جاية."

7 — The order journeyرحيق1.5 دقيقة

"الطلب بيعدّي بـ 5 حالات: PLACED → ACCEPTED → READY → PICKED_UP → DELIVERED. ده State Machine: كل انتقال مسموح لدور معيّن بس، يعني العميل ميقدرش يقبل طلبه بنفسه، والمندوب ميقدرش يستلم قبل جاهز. المطعم عنده 15 دقيقة يرد وإلا الطلب بيتلغي لوحده، ولو مفيش مندوب خده في 40 دقيقة بيتلغي برضه. وكل خطوة بتوصل للكل فوراً بـ Server-Sent Events." وبعدين: "عبد الرحمن هيوريكم لوحة الأدمن."

8 — Administration dashboardعبد الرحمن1 دقيقة

"لوحة الأدمن صفحة ويب (HTML وCSS وJavaScript) بتكلم نفس الـ API. منها بيدير المطاعم والمنيو، والمناطق ورسومها، والمستخدمين، والطلبات، والكوبونات، والشكاوى، وأرقام اليوم. حسابات المطاعم والمناديب الأدمن بس اللي بيعملها، العميل بس هو اللي بيسجّل لنفسه. وكل حاجة الأدمن بيعملها بتتسجّل في audit log."

9 — What makes VELOX differentعبد الرحمن1 دقيقة

"هاتلي أي حاجة: العميل يكتب عايز إيه ومن أنهي محل، والمندوب يشتريها ويجيبها. والعلامة المميزة زي 'جنب الصيدلية' جزء أساسي من العنوان، لأن الناس هنا بتوصف كده، وبتظهر للمندوب بلون مختلف. والمناديب من البلد، وتتبع لايف، وعربي وإنجليزي." وبعدين: "نبيه هيشرح التكنولوجيا."

10 — Technology stackنبيه1 دقيقة

"السيرفر Java 17 بـ Spring Boot وMaven، وقاعدة البيانات PostgreSQL بـ JDBC وFlyway (22 جدول)، والتطبيق Flutter (كود واحد لأندرويد والمتصفح)، والإشعارات Firebase، والخرايط OpenStreetMap، والتشغيل كله بـ Docker بدبل كليك، والاختبارات JUnit وPostman وSelenium وJMeter." متشرحش كل أداة بالتفصيل، قول ليه اخترناها بس.

11 — Architectureنبيه1 دقيقة

"كل الواجهات (التطبيق والموقع ولوحة الأدمن) بتكلم API واحد بـ HTTPS وJSON. جوه السيرفر كل طلب بيعدّي على 3 طبقات: Controller → Service → Repository. الـ Controller بيستقبل، والـ Service فيه القواعد والصلاحيات، والـ Repository بيكلم قاعدة البيانات بـ JDBC. والسيرفر مقسّم 7 أجزاء، كل واحد في التيم مسؤول عن جزء."

12 — Securityنبيه1.5 دقيقة

"اللي جوه السيستم: الباسورد متخزن بـ PBKDF2 بـ 210 ألف لفة وsalt، والتوكن موقّع وبيبطل لو الباسورد اتغير، وفيه فحص صلاحية على كل طلب (مفيش IDOR)، وبعد 5 محاولات غلط الحساب بيتقفل، وكل الـ SQL بـ parameters فمفيش SQL Injection.
وهاجمنا السيستم بنفسنا بـ Burp Suite. أخطر حاجة لقيناها: التطبيق كان بيقبل أي لينك سيرفر من قناة عامة، فممكن حد يحوّل الموبايلات لسيرفر بتاعه ويسرق الباسوردات. قفلناها. ولما اتعلن عن Java2Shell في Java 17، اتأكدنا إذا كنا متأثرين وقفلناها في نفس اليوم." وبعدين: "رحيق هتوريكم الاختبارات."

13 — Testing & qualityرحيق1 دقيقة

"عملنا Manual وAutomated وAPI وLoad: 97 اختبار JUnit كلهم ناجحين، منهم اختبارات بتشغّل PostgreSQL حقيقي في Docker. و45 فحص للرحلة كاملة على السيرفر الحقيقي. و30 طلب في Postman فيهم هجمات. و47 حالة اختبار يدوي اتقسمت علينا. وJMeter بـ 100 مستخدم في نفس الوقت. واختباراتنا لقت مشاكل: البطء مع قاعدة البيانات البعيدة، واختبار مكانش معزول، وسجّلنا الاتنين." وبعدين: "يلا نوريكم السيستم شغال."

٣) الديمو: 5 دقايق بالظبط

قبل ما الدكتور يدخل (على لابتوب نبيه، والـ VELOX شغال بـ START-VELOX.bat):
• Chrome ← localhost:8080/app ← داخل كـ عميل
• Chrome Incognito ← 127.0.0.1:8080/app ← داخل كـ مطعم ناصف
• Edge ← localhost:8080/app ← داخل كـ مندوب، وعامل أونلاين ✅
• تاب ← localhost:8080/admin ← داخل كـ أدمن، وتاب ← localhost:8080/swagger-ui.html
• الفيديو المتسجّل مفتوح وجاهز لو حاجة وقعت.
#مينبيعمل إيهبيقول إيه
1فاديChrome (العميل): مطعم ناصف ← صنفين ← ملاحظة "من غير بصل" ← العنوان والعلامة المميزة ← كاش ← تأكيد"شايفين السعر كامل ورسوم التوصيل قبل ما أأكّد"
2رحيقIncognito (المطعم): الطلب يظهر بصوت لوحده ← قبول ← جاهز"من غير Refresh، والعدّاد بيتغير"
3فاديEdge (المندوب): الكارت فيه الأصناف والعنوان والكاش ← خد الطلب ← استلمت ← سلّمت. والعميل شايف التتبع"المندوب شايف كل اللي محتاجه، وأرباحه زادت"
4عبد الرحمنلوحة الأدمن: الطلب بحالته وأرقام اليوم"الأدمن شايف كل حاجة"
5نبيهفي Swagger: ١) GET /api/admin/users ← Try it out ← Execute من غير توكن ← 401. ٢) POST /api/auth/login بإيميل وباسورد العميل ← انسخ الـ token من الرد ← زرار Authorize فوق ← الصقه ← نفذ /api/admin/users تاني ← 403. ٣) POST /api/auth/login والإيميل ' OR 1=1 -- ← مرفوض (401). جهّز الخطوات دي قبلها وجرّبها مرة."ده الأمان اللي اتكلمنا عنه، شغال قدامكم"
لو حاجة وقعت: الطلب مش ظاهر ← 🔄 في الصفحة. صفحة بيضا ← Ctrl+Shift+R. VELOX مبيردش ← docker compose --profile app restart api. لو كل حاجة وقعت ← الفيديو. وكمّلوا بهدوء، الدكتور عارف إن الديمو ممكن يقف.
