Security · Penetration Testing track

Secure by design, then attacked by us

BUILT IN

  • Passwords: PBKDF2-SHA256, 210,000 rounds + salt
  • Signed sign-in tokens, revoked on password change
  • Role and ownership check on every action (no IDOR)
  • Locked after 5 wrong passwords (HTTP 429)
  • Only parameterized SQL: no injection
  • SpotBugs + FindSecBugs, CodeQL, OWASP ZAP

WE ATTACKED OUR OWN SYSTEM

  • Critical: server-link hijack in the app, fixed
  • High: cleartext HTTP and token in backups, fixed
  • High: unlimited payment-code guessing, fixed
  • Java2Shell (CVE-2026-114938): checked and mitigated the day it was published

VELOX

Presenter: Nabeeh. Each member ran Burp Suite attacks on their own module (IDOR, missing auth, wrong role, price tampering, XSS, SQL injection) and wrote it up in security/. Explain one finding in detail: the app accepted any server link from a public channel, so an attacker could redirect phones and steal passwords; now only Cloudflare links are accepted and release builds are locked to one server.
